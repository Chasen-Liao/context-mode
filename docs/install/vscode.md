# Install context-mode v2 for VS Code

This guide is for VS Code's built-in Copilot Chat agent (the "Local" harness). It covers install,
MCP server setup, hooks, verify, update, upgrade from v1, rollback, uninstall and troubleshooting.

Checked 2026-10-17 against VS Code 1.142.0.

## 1. Requirements

- VS Code 1.142 or later. Check your version:
  ```bash
  code --version
  ```
  (Source: [code.visualstudio.com/docs/configure/command-line](https://code.visualstudio.com/docs/configure/command-line), checked 2026-10-17.)
- If you do not have VS Code yet, install it first:

  | OS | Command |
  |---|---|
  | macOS | `brew install --cask visual-studio-code` |
  | Windows | `winget install -e --id Microsoft.VisualStudioCode` |
  | Linux (apt) | `sudo apt install code` (after adding the Microsoft repo) |

  (Source: [code.visualstudio.com/docs/setup](https://code.visualstudio.com/docs/setup), checked 2026-10-17.)
- On macOS/Windows/Linux the installer puts `code` on your PATH. If `code` is missing on macOS, run
  **Shell Command: Install 'code' command in PATH** from the Command Palette.

## 2. Install context-mode (MCP server)

v2 adds context-mode as an MCP server entry. There is no marketplace plugin for VS Code; you add one
config entry.

1. Open the Command Palette and run **MCP: Add Server**. Pick **stdio**, then **Workspace**.
2. Or add the entry by hand to `.vscode/mcp.json` in the project root:
   ```json
   {
     "servers": {
       "context-mode": {
         "command": "node",
         "args": ["<path-to-context-mode>/dist/server/main.js", "--agent", "vscode"]
       }
     }
   }
   ```
3. Or use the CLI, which writes to your **user** profile instead of the workspace:
   ```bash
   code --add-mcp "{\"name\":\"context-mode\",\"command\":\"node\",\"args\":[\"<path-to-context-mode>/dist/server/main.js\",\"--agent\",\"vscode\"]}"
   ```

(Source: [code.visualstudio.com/docs/agent-customization/mcp-servers](https://code.visualstudio.com/docs/agent-customization/mcp-servers), checked 2026-10-17.)

## 3. Add hooks

VS Code's Local harness reads hook files from:

| Location | Scope |
|---|---|
| `.github/hooks/*.json` | Workspace (this is the one context-mode uses) |
| `~/.copilot/hooks/*.json` | User |

Write the context-mode hooks to `.github/hooks/context-mode.json`. Sample shape (full file is
generated by the installer, do not hand-write it):
```json
{
  "hooks": {
    "SessionStart": [{ "type": "command", "command": "<...>", "timeout": 5 }],
    "UserPromptSubmit": [{ "type": "command", "command": "<...>", "timeout": 5 }],
    "PreToolUse": [{ "type": "command", "command": "<...>", "timeout": 5 }],
    "PostToolUse": [{ "type": "command", "command": "<...>", "timeout": 5 }]
  }
}
```
Two settings must be on (both are on by default):
- `chat.useHooks` — turns hooks on.
- Hook files only run once you trust the workspace.

(Source: [code.visualstudio.com/docs/agent-customization/hooks](https://code.visualstudio.com/docs/agent-customization/hooks), checked 2026-10-17.)

## 4. Verify the install

Run the doctor check:
```
/ctx-doctor
```
in VS Code chat. It prints one row per check (MCP entry found, hooks found, DB reachable). Fix any
row marked failed before you continue.

## 5. Update context-mode

There is no one-command update for a git-sourced MCP server in VS Code (test-first row, ADR-0011).
Today's step:
1. Pull the latest context-mode build.
2. Re-run `code --add-mcp` (step 2.3) with the new path, or edit `.vscode/mcp.json` by hand.
3. Reload VS Code (Command Palette: **Developer: Reload Window**).
4. Run `/ctx-doctor` again to confirm the new version.

## 6. Upgrade from v1

Order matters (ADR-0011, ADR-0017 R3): install v2 first, then run `/ctx-upgrade`, and only then
remove v1.

1. Add the v2 MCP entry and hooks (steps 2–3 above). Keep the old v1 entry for now.
2. Run `/ctx-upgrade` in VS Code chat. It:
   - deletes the v1 hook file `.github/hooks/context-mode.json` (the old one; step 3 above writes the
     new one under the same path, so do step 3 after this if both exist),
   - deletes v1 session data under `.github/context-mode/sessions/` (project scope) or
     `~/.vscode/context-mode/sessions/`,
   - flags a leftover context-mode entry inside `.vscode/mcp.json` if one is left pointing at the v1
     binary.
3. If you installed v1 via `npm install -g context-mode`, remove it last:
   ```bash
   npm uninstall -g context-mode
   ```
   Until this step, v1's global `context-mode` bin still exists, but step 2 already pointed VS Code at
   the v2 entry, so nothing breaks.
4. Run `/ctx-doctor` once more. It should show a clean table (no v1 leftovers).

## 7. Roll back to v1

1. Remove the v2 MCP entry: open `.vscode/mcp.json` (or run **MCP: List Servers**, select
   `context-mode`, then remove it) and delete the `context-mode` entry.
2. Remove the v2 hook file: `.github/hooks/context-mode.json`.
3. Re-add the v1 entry you removed in step 6.1, or reinstall v1:
   ```bash
   npm install -g context-mode
   ```
4. Reload VS Code.

There is no automated rollback command for VS Code (same limitation as Gemini/Qwen, ADR-0011). Treat
this as a manual, documented path.

## 8. Uninstall

1. Remove the MCP entry from `.vscode/mcp.json` (or **MCP: List Servers** → select → remove).
2. Delete the hook file: `.github/hooks/context-mode.json`.
3. Delete session data: `.github/context-mode/sessions/` (project scope) or
   `~/.vscode/context-mode/sessions/` (user scope).
4. If you installed the context-mode CLI itself via npm, remove it:
   ```bash
   npm uninstall -g context-mode
   ```

`/ctx-upgrade` with `mode: uninstall` and `confirmDelete: true` does steps 1–3 for you; without
`confirmDelete: true` it stops the server and removes config entries but keeps your session data.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| `/ctx-doctor` shows no MCP entry found | Re-check `.vscode/mcp.json` — the top-level key must be `servers`, not `mcpServers` (that key is for the separate portable-Copilot format, a different file). |
| Hooks never fire | Check `chat.useHooks` is `true` and the workspace is trusted. Also check `chat.hookFilesLocations` has not turned off `.github/hooks/context-mode.json`. |
| Hook fires but context-mode sees no tool name match | VS Code's Local harness ignores a Claude-style `matcher` field — every command for the event runs, and context-mode filters inside the hook body instead. This is expected, not a bug. |
| `code --add-mcp` writes to the wrong profile | The CLI always writes to your **user** profile. For a workspace-only entry, edit `.vscode/mcp.json` directly instead. |
| Session data left after uninstall | Check both possible paths — project scope (`.github/context-mode/sessions/`) and user scope (`~/.vscode/context-mode/sessions/`) — `ctx_doctor` reports both. |

## Differences from the v2 spec

These points disagree with `docs/v2/impl/10-adapters.md` §7 ("vscode" row) or ADR-0011. The impl file
is not edited here; record the disagreement only.

1. **No git-ref plugin install.** `impl/10-adapters.md` §1.3 lists `vscode`'s `installMode` as
   `"mcp-entry"` — a plain config entry, not a marketplace/plugin install. This guide confirms that is
   correct: VS Code has no CLI or UI path to install an MCP server or a hook set "from a git ref" the
   way Gemini (`gemini extensions install <url> --ref release`) or Pi do. The only way to point VS Code
   at a specific git ref is to `git clone` it yourself and put the resulting path into the MCP entry's
   `command`/`args` by hand. ADR-0011's release table marks VS Code "test first, then document" for
   exactly this reason — there is no update command to test.
2. **No CLI remove for an MCP server.** The official docs only give `code --add-mcp`. There is no
   `--remove-mcp` flag. Removing the entry needs the Command Palette or a hand-edit of `mcp.json`. The
   spec files do not claim otherwise, but a reader could assume CLI symmetry; this guide states the gap
   explicitly.
3. **Hooks feature is in Preview.** VS Code's own docs mark the whole hooks feature "Preview" as of
   1.142. `impl/10-adapters.md` does not flag this; it is worth tracking because a Preview feature can
   change shape between VS Code releases without a major-version bump.
4. **`.vscode/mcp.json` cleanup is a flag, not a delete.** ADR-0011's VS Code row says `ctx_doctor`
   "flags" a leftover context-mode entry inside `.vscode/mcp.json`, the same as a user-added Claude Code
   MCP entry — it does not say `ctx_upgrade` removes it automatically. This guide's step 6.2 states this
   plainly so a reader does not expect an automatic removal there.
